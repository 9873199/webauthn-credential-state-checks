## 改动概览

### 核心实现 — `fido2/server.py`

**新增 `WebAuthnCredential` 凭据记录类**（frozen dataclass），包含注册结果中应持久化的全部字段：
- `credential_data`（公钥数据 + credential ID）、`user_handle`（账户）、`sign_count`、`backup_eligible`（BE）、`backup_state`（BS）
- `WebAuthnCredential.from_registration(user_handle, auth_data)` 从 `register_complete` 返回的、被签名覆盖的 `AuthenticatorData` 构建记录，不采信客户端字段

**`authenticate_begin` 现在把范围绑定进 state**：
- 预选账户路线：允许的 credential ID（base64url，保持 state 可 JSON 序列化存入 session）和账户 user handle 写入 state；同一请求混入不同账户的凭据直接报错
- 可发现凭据路线（`credentials=None`）：state 显式标记无预选账户

**新增显式启用的入口 `authenticate_complete_stateful`**：
- **预选账户**：credential ID 必须在 state 绑定集合内——complete 传入再大的凭据集合也不能扩范围；userHandle 可省略，提供则必须与账户逐字节匹配
- **可发现凭据**：userHandle 必填，必须同时按 rawId + userHandle 匹配已登记记录，只按 rawId 不认人
- **备份位**：BS=1/BE=0 非法拒绝；BE 与登记值不同拒绝；合法 BS 切换接受
- **计数器**：新旧任一非零则必须严格递增；双零放行
- 所有标志/计数器均取自签名覆盖的 `AuthenticatorData`，客户端自塞的 `backupEligible`/`backupState`/`signCount` 等同名字段被忽略
- challenge、origin、RP ID、UP、UV、签名检查全部保留（抽到共享的 `_verify_assertion_base`，两条入口共用，无旁路）
- 失败不修改调用者任何记录或 state；成功返回**新的** `WebAuthnCredential`（更新后的 signCount/BS）和可保存的新 state dict；旧 `authenticate_complete` 行为不变

### 测试 — `tests/test_server_stateful.py`（33 个，全部通过）

用内存 EC 密钥生成**真实 ECDSA 签名**的软件"认证器"，无需浏览器/USB，覆盖：跨账户替换、begin 后扩范围、complete 时偷换账户绑定、计数器倒退/零计数器/零转非零、BS=1+BE=0、BE 变更、合法 BS 切换、错误签名、错误 challenge/origin/RP ID、缺 UP、UV 强制、客户端伪造同名字段、state JSON 往返、失败不可变性，以及旧接口兼容性。
